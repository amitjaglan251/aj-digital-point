API NOT CONNECTED

Before development

  1. Choose a PAN service provider and obtain written authorization for the intended service category.
  2. Confirm the provider's API agreement, production eligibility, pricing, permitted use, support process and audit requirements.
  3. Obtain official API documentation, sandbox access and test credentials from the provider's authorized channel.
  4. Complete legal/privacy review, customer consent language, grievance contact, retention/deletion rules and incident response plan.

Required secure architecture

  • Use a server-side backend; never put API secrets, private keys or provider tokens in browser JavaScript or a public GitHub repository.
  • Store secrets in a managed secret store or protected server environment, rotate them and restrict access.
  • Use HTTPS, authenticated staff access, least-privilege roles, request validation, rate limits, audit logs and monitoring.
  • Collect only data required by the approved workflow. Avoid logging Aadhaar/PAN/OTP or full document contents.
  • Use provider-hosted identity verification wherever required. Do not create an independent Aadhaar OTP flow or a searchable PAN database.
  • Test only with provider-approved sandbox/test data; add timeout handling, safe error messages and duplicate-request protection.

Go-live checklist

  • Written provider approval and production credentials confirmed.
  • Privacy notice and consent reviewed and published.
  • Security testing and access-control review completed.
  • Fees, refund/cancellation terms and customer support details published accurately.
  • End-to-end tests passed with approved test cases.
  • Monitoring, incident response and credential rotation documented.
Current state: This page is a planning checklist only. No live API, PAN lookup, Aadhaar verification, OTP sending, document upload, payment collection or application submission is implemented here. Do not enter or send personal identifiers on this page.
